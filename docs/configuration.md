# Configuration

Every setting is in a `.jsonc` file (JSON that allows `//` comments and trailing commas). The
files are commented throughout, so open them for the details. Paths below are relative to the
project folder (or to the app's working folder, see the end of this page).

## `config/`

| File | What it sets |
|---|---|
| `robot.jsonc` | **BuzzBot**, the default robot: size, mass and center of gravity, battery, hub timing, drivetrain, IMU, motors, mechanisms (lift, arm…), servos, CR servos, intake, hopper, launcher, grippers, sensors, odometry pods, Pinpoint/OTOS, Limelight and webcams. Device names must match the names used in team code. |
| `robot.glb`, `robot.model.jsonc` | BuzzBot's 3D model, and how it sits on the robot and which parts move. Generated by `tools/BuzzBotCad.java`. |
| `robot.calibrated.jsonc` | Written by `./gradlew calibrate`. It doesn't exist until you calibrate. The original `robot.jsonc` is never changed. |
| `field.jsonc` | The field: BIOBUZZ, 141.17 in between wall faces, tile size, start positions (Red/Blue Wall, Red/Blue Audience), and the season's own values (HIVE, ball masses, tip threshold…). |
| `web-view.jsonc` | The view-only browser page: on/off, port 8766, who can watch (`local`, `tailscale`, `network`). `local` by default. |
| `agent-api.jsonc` | The agent API inside the window: on/off, port 8767, token, read-only files, `java_eval`. |
| `examples/starter-robot.jsonc`, `examples/blank-field.jsonc` | A simple starting robot and an empty field to copy from. |
| `parts/` (optional) | Your team's own parts, added to the built-in catalog (`sim-core/src/main/resources/parts/catalog.jsonc`). |

Some values are estimates rather than measurements, for example the HIVE tip threshold and
some motor curves. They're marked in the files. The user guide's
[What's simulated](../README.md#whats-simulated) section lists them.

**`allowNetworkOnWindows`** (in `web-view.jsonc`, `false` by default). The first time a program on
Windows opens a page to other computers, Windows Defender Firewall shows a prompt that only an
administrator can accept. The simulator never asks for an administrator by itself, so on Windows
the page is served to this computer only, whatever `access` says, until this is `true` as well.
The Console says so next to the page's address. Macs and Linux ignore it.

## Robot packages: `robots/<name>/`

A robot package is a whole robot in one folder. Pick it in the window (Setup → Robot & field), or
create one with **Import robot…**, which builds `robot.jsonc` from the `hardwareMap` calls it
finds in the code.

```
robots/<name>/
  robot.jsonc          the simulated robot (device names as in the code)
  code/                the team's Java code (or "code": { "dirs": [...] } to point elsewhere)
  robot.glb            CAD export (GLB/glTF, STL or OBJ)
  robot.model.jsonc    how the CAD model sits and which parts move
  libs/                extra .jar libraries (optional)
  parts/               extra parts (optional)
```

The window compiles `code/` when it opens the robot and lists only that robot's OpModes. Put your
own team's robot in a folder of its own here, or anywhere (`"code": { "dirs": [...] }`). A clone
of your team's repository can sit in `robots/<name>/repo/`, which the agent API treats as read-only.

| Package | What it is |
|---|---|
| `ExampleBot` | A small example with a CAD model. |
| `RoadRunnerQuickstart` | The unmodified Road Runner 1.0 quickstart. |
| `PedroQuickstart` | The unmodified Pedro Pathing quickstart. |

## TeamCode

`TeamCode/` is the project's own robot code, which the window runs by default:

- `buzzbot/`: BuzzBot's autos (red and blue), TeleOp, launcher tuner, drive, intake, lift,
  launcher, localizer, the `HiveTags` AprilTag aiming code, and driver aids.
- `calibration/`: the Calibrate Drive, Turn, Mechanism and IMU OpModes. Run them on the real
  robot, then feed their logs to `./gradlew calibrate`.
- Starter examples: `EncoderDriveAuto`, `MecanumTeleOp`, `IterativeTimedSquare`, and two FTCLib
  examples.

It compiles at Java 8 against the shim, with FTCLib, Road Runner 1.0, Pedro Pathing 3 and Ivy
available (`TeamCode/build.gradle`). To use the simulator for your own team, put your code in
`TeamCode/src/main/java` (or make a robot package).

## Where each way of running it reads its config

| Way of running | Config folder |
|---|---|
| `./gradlew run`, `Run Simulator.bat`, the Mac launcher app (`installMacApp`), headless, agent API | `config/` and `robots/` in the project |
| Windows app (`FTC Test Suite.exe`, or the one-file `.exe`) | `%USERPROFILE%\FTC Sim\Workspaces\App\config\`, or the folder given with `--home` |
| Mac app from the DMG | `~/FTC Sim/Workspaces/App/config/` |
| The demos | `…/FTC Sim/Workspaces/Demo/config/` (refilled at each launch) |

So a change in the project's `config/` doesn't reach an installed app's working folder: each has
its own copy, made from the starter files the first time the app opens it, and never replaced.
