# Agent API guide

The agent API lets AI agents (Claude Code, Cursor, Codex, or any MCP client) and scripts drive
the simulator. They can compile team code, run OpModes with scripted gamepads, record what the
robot did, play matches and look at the field. Use it to test code changes or try a new
mechanism without opening the window.

Every tool's arguments are listed in the [tool reference](agent-tools.md), which is generated by
`tools\ftc-sim-mcp.cmd --docs`. This page covers how to connect and how to use the tools.

## Two ways in

| | Headless server | Server inside the window |
|---|---|---|
| Start | `tools\ftc-sim-mcp.cmd` (MCP over stdio). The agent starts it. | Opens with the simulator window. |
| Simulations | Headless sessions you create (`sim_create`). They're lockstep: as fast as the computer allows, and repeatable. | Headless sessions, plus the window's own simulation as session `"live"`, in real time. |
| Needs the window | No | Yes |
| Access | Whatever starts it | `127.0.0.1` only, with a token. Requests from web pages are refused. |
| Settings | Command-line options | `config/agent-api.jsonc` (on, port 8767) |

### Claude Code

`.mcp.json` in this folder registers the headless server as `ftc-sim`: open Claude Code here
and approve the server when asked. It runs `tools\ftc-sim-mcp.cmd`, which finds Java 21 by
itself (downloading it once if the PC has none) and builds the simulator the first time and
after code changes. Build output goes to stderr, so it never mixes with MCP messages.

To give an agent the open window too, use **File › Copy Agent Connection** in the window. It
copies a `claude mcp add …` command that includes this computer's token. Run it in a terminal.

### Other clients and scripts

```bat
tools\ftc-sim-mcp.cmd                  # MCP over stdio, headless (the usual way)
tools\ftc-sim-mcp.cmd --live           # MCP over stdio, passed on to the open window
tools\ftc-sim-mcp.cmd --http [PORT]    # MCP + REST on 127.0.0.1 (token: --token or FTC_SIM_TOKEN)
tools\ftc-sim-mcp.cmd --docs           # print the tool reference
tools\ftc-sim-mcp.cmd --project DIR    # use another simulator folder
```

Over HTTP (the window's server, or `--http`):

| Route | What |
|---|---|
| `POST /mcp` | MCP (JSON replies, no event stream) |
| `GET /api/tools` | The tool list |
| `POST /api/tools/NAME` | Calls one tool. The body is its JSON arguments. |
| `GET /api/docs/guide`, `/api/docs/tools`, `/api/docs/readme` | This guide, the reference, the README |
| `GET /api/health` | Up check (the only route without a token) |

Every route except `health` needs `Authorization: Bearer TOKEN`. In the window, the token is the
one in `config/agent-api.jsonc`, or, when that's empty, a random token kept in this computer's
user settings. `--live` finds that token by itself.

## Workflows

Start every task with **`project_info`**. It returns the configs, team code folders, robot
packages, units and coordinate system, open sessions, and what this server allows.

**Test an OpMode in one call.** Use `sim_create`, then `opmode_run` with `{opmode, seconds,
gamepad script, record channels, image}`. It reports how the OpMode ended, any crash with the
line of robot code, the telemetry, how far the robot moved, the loop time and the printed output.

**Step by step.** Use `opmode_control` (init/start/stop), `gamepad`, `sim_step` (until
`opmode_stopped` or `robot_stopped`), `sim_state` (pose, motors, servos, mechanisms, sensors,
odometry, score) and `sim_record` (a table over time).

**Change code.**
1. `write_file` the change.
2. `compile_code` for errors with file and line.
3. A new `sim_create`. Sessions keep the code they compiled.

To try a change *without* editing the project, pass the changed files to `sim_create` or
`compile_code` as `sources`.

**Try a new mechanism.** Call `sim_create` with `robot_config` text. `validate_robot_config` and
`parts_catalog` help write that config.

**Play a match.** `match {auto, teleop}` returns the score breakdown and the referee notes.

**See it.** `sim_image` draws the 2D field for any session. In the live session, `ui
screenshot` captures the window.

**Debug.**
- `console_read` shows printed output and warnings.
- `hardware` reads any device or calls any method on it.
- `java_eval` runs Java inside the simulator against the session and the team code. Turn it off
  with `"javaEval": false` in `config/agent-api.jsonc`.

The server also offers MCP prompts for common jobs: `test_opmode`, `check_team_code`,
`tune_mechanism`, `add_mechanism` and `play_match`.

## Units and coordinates

Inches and degrees. The origin is the field center. +x points toward the blue alliance wall
and +y away from the audience. Heading 0 points along +x, and counter-clockwise is positive.

## Rules agents should follow

- `robots/*/repo/**` is read-only (`readOnly` in `config/agent-api.jsonc`). It's a team's own
  repository and must stay unmodified. Test changes to it with `sources` instead.
- Headless sessions are repeatable. If a result changes between runs, the code changed, or it
  depends on something outside the simulation.

## Troubleshooting

| Problem | Fix |
|---|---|
| "The simulator window isn't serving agents" (`--live`) | Open the window and check `"enabled": true` in `config/agent-api.jsonc`. Then reload with F5. |
| 401 / "Missing or wrong token" | Copy the connection again (File › Copy Agent Connection), or set the same `"token"` in the config and on the client. |
| "couldn't start on port 8767" | Another program uses the port. Change `"port"`. |
| The build fails when the server starts | The error is on stderr. Run `gradlew installDist` to see it in full. |
| Timing looks wrong in a plain `java` run | Code started without the clock agent runs on wall-clock time. Use `tools\ftc-sim-mcp.cmd` or Gradle, which load it. |
